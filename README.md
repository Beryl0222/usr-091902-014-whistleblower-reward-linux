# 市场举报奖励

隔离举报身份，衔接案件贡献认定、奖励建议、财政会签与支付。

## 设计要点

- **身份封存**：登记线索时真实身份进入 `IdentityVault`，对承办、审核、财政、对外各环节只发放稳定别名（举报人A…）；同一人跨案件复用同一别名，同一内容重复举报自动识别。身份仅在支付等法定需要时凭理由揭示，并写入不可绕过的审计记录。
- **贡献顺序**：同一违法行为分别认定全案唯一的“最先有效贡献”与后来出现的“独立关键贡献”，重复举报无奖励资格；同一人的多条线索按人归并。
- **系统算奖，禁止手填**：案件结案进入“可奖励”阶段时，按违法类别、举报等级（一/二/三级）、贡献顺序、罚没结果与**结案当日生效的规则版本**自动生成建议金额（`fixtures/reward_rules.json`，v2022 与 v2025 两版，最高 100 万元，内部举报上浮）。无罚没款案件适用定额奖励。
- **权限与会签**：建议金额达到 20 万元自动转财政会签；**任何人不得既承办案件又批准自己的建议**，财政会签人同样不得是承办人。
- **追加决定，旧结论留存**：撤回、行政复议、判决改变罚没结果均生成追加决定（补差/追缴/维持），旧决定标记“已调整”但完整保留；复议按事件当日生效规则重算。支付前撤回终止奖励，支付后撤回生成追缴。
- **逐人可说明**：`reporter_explanations` 对每名举报人给出资格、资格理由、适用规则版本、建议金额、当前待办审批与累计实际支付。

## 运行

```bash
python3 service.py --check     # 校验规则配置
python3 service.py --port 8000 # 启动服务
npm test                       # 运行服务契约与领域场景测试（21 项）
```

## 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/health` | 健康检查 |
| POST | `/reports` | 登记线索（身份封存，返回别名；自动识别重复） |
| POST | `/reports/{id}/evidence` | 补充证据 |
| POST | `/reports/{id}/link` | 关联案件 |
| POST | `/reports/{id}/withdraw` | 撤回举报 |
| POST | `/cases` | 立案（自动关联同一违法行为的线索） |
| POST | `/cases/{id}/recognize` | 贡献顺序与举报等级认定 |
| POST | `/cases/{id}/close` | 结案进入可奖励阶段，生成建议金额 |
| POST | `/cases/{id}/review` | 复议/判决变化，按当日规则追加决定 |
| POST | `/rewards/{id}/approve` | 审核批准（可附精神奖励；超权限转财政） |
| POST | `/rewards/{id}/countersign` | 财政会签 |
| POST | `/rewards/{id}/pay` | 支付（此时才揭示身份并留审计） |
| POST | `/rewards/{id}/clawback` | 追缴执行 |
| GET | `/cases/{id}/brief` | 承办视图：仅别名、证据编号 |
| GET | `/cases/{id}/worklog` | 普通办案日志：无身份信息 |
| GET | `/cases/{id}/external` | 对外材料：顺序代称，无别名无身份 |
| GET | `/cases/{id}/explanations` | 逐人资格/待办/实付说明 |

业务规则冲突返回 HTTP 422；未知路由返回 404。`fixtures/domain.json` 统一领域称谓，`fixtures/reward_rules.json` 保存版本化奖励规则。
